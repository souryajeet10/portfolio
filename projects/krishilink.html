01 — OVERVIEW

Project Context & Objectives

What It Is

A decision layer for agricultural commerce that calculates true net realization for crops after subtracting logistics and market levies.

Problem Addressed

Farmers frequently travel to distant markets quoting marginally higher prices, only to find transit expenses and spoilage erase their profit margins.

What I Built

Designed an accessible mobile interface powered by REST endpoints aggregating Agmarknet/e-NAM data, paired with a net realization decision algorithm and voice queries.

02 — KEY FEATURES

Core Capabilities

Market Data

Aggregated live commodity rates from government mandis via e-NAM and Agmarknet public feeds.

Price Analysis

Net-income calculation factoring in distance, haulage logistics, and mandi commission fees.

Buyer Discovery

Curated directory of verified regional buyers, collection hubs, and institutional purchasers.

Multilingual Interface

Localized interfaces designed to overcome linguistic barriers in regional agricultural belts.

Voice-First Interaction

Audio query input enabling farmers to request crop prices effortlessly without complex typing.

04 — HOW IT WORKS

System Workflow & Architecture

The farmer speaks or selects crop type and quantity. The system pulls current prices from nearby mandis, computes haulage cost per kilometer, and recommends the destination maximizing net take-home revenue.

01

Crop & Volume Entry

Farmer provides crop name and harvest weight via voice or touch.

02

API Rate Aggregation

Engine queries e-NAM and Agmarknet feeds for regional mandi price quotes.

03

Net Calculation

Algorithm subtracts distance travel fees and loading charges from gross value.

04

Optimal Recommendation

Presents clear ranking showing which mandi yields highest net profit.

Data Pipeline & Interaction Flow
Mobile Client ↓ Voice / Crop Query API Aggregator
API Aggregator ↓ Real-time Mandi Feeds e-NAM & Agmarknet
Decision Engine ↓ Ranked Net Income Matrix Farmer UI

06 — CHALLENGES & LEARNINGS

Engineering Takeaways

What Was Difficult

Dealing with disparate data schemas from public agricultural registries and designing an interface accessible for non-technical users.

Technical Decisions

Simplified interface design with large tactile buttons, clear green/amber indicator badges, and voice prompts.

What I Learned

Learned the crucial importance of user-centric empathy in software design — building tech that solves real economic challenges.
